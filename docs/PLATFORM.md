# Vekto platform

## Runtime

The application runs independently of AI. D1 holds subjects, topic sections, subtopics, questions, answer keys, exam specifications, scale tables, profiles, sessions, saved responses and results. `/api/platform` reads and writes only D1. Questions are not generated at test start.

Schema migrations in `drizzle/` contain schema only. `/api/platform/bootstrap` installs versioned, preclassified data once per subject; its repeated calls are read-only version checks. The deployment seed is prepared by `scripts/prepare-platform-bank.ts`. Data import never changes historical question snapshots.

`learning_sessions` stores ownership, server deadlines, current stage, revision, config snapshot and final result. `session_items` stores an immutable question snapshot plus saved answer, flag and practice reveal state. Every read and write is scoped to the profile cookie/identity. Atomic revision-guarded batches prevent stale writes and double completion. A partial unique index allows one unfinished session per profile.

Guest mode remains enabled at the user's request. Guest identity is an HTTP-only cookie; records are on the server, not localStorage. Clearing the cookie loses access to that guest profile. Cross-device account sync is not implemented.

| Subject | Questions | Formats | Raw maximum |
|---|---:|---|---:|
| Ukrainian | 30 | 25 single, 5 matching × 4 | 45 |
| Mathematics | 22 | 15 single, 3 matching × 3, 4 numeric × 2 | 32 |
| History | 30 | 20 single, 4 matching × 4, 3 ordering × 3, 3 choose-three × 3 | 54 |
| English / German | 32 | 5 single, 11 language matching, 16 gap fill | 32 |
| Biology | 30 | 24 single, 4 matching × 4, 2 three-group × 3 | 46 |
| Geography | 30 | 20 single, 4 numeric × 2, 6 choose-three × 3 | 46 |

Stage 1: Ukrainian + mathematics, 120 minutes. Break: 20 minutes. Stage 2: history + selected optional subject, 120 minutes. Navigation within a stage is unrestricted. Answers count only when saved. Stage 1 cannot be revisited. The server expires the stage when it is next requested; the browser polls the deadline. Reopening cannot reset the timer. The second stage starts when the participant continues after the break.

Practice is scored as earned/available raw points, not an invented 100–200 estimate. Simulations use the exact per-subject conversion maps; below-threshold scores remain null. Sources:

## Content limits

The bank contains 412 published 2025 NMT questions and authored practice material. It is not a claim to contain all real NMT tasks or complete coverage of every subtopic. Simulations choose intact published variants, preserving shared passages and question order, with preference for variants least previously encountered. Training prefers unseen canonical questions, then least-exposed questions. Technical duplicates are archived (`active=0`) without deleting rows referenced by older results.

The source taxonomy is refined during offline import, not generated by AI at runtime. Explicit `section` and `subtopic` tags override automatic keyword classification. Unfilled syllabus topics are displayed honestly. Editorial review and expansion of underfilled topics remain necessary. Images currently reference source URLs; if an upstream image is removed it needs to be replaced with a licensed stored asset.

## Add thousands of tasks without changing the player

1. Prepare `{ "questions": [...] }` JSON. Use the existing source question schema plus explicit `section` and `subtopic`. Each question needs an immutable unique ID, answer key, explanation and attribution. Original NMT tasks require an original PDF URL. Do not label authored questions as official.
2. Validate: `npx tsx scripts/import-questions.ts /absolute/path/questions.json`. Review content and answer correctness. Add `--apply` only when approved.
3. Increment the data release version in the bank preparation script. Run `npm run db:export` to classify/deduplicate and export. Runtime code and answer controls do not change.
4. Run scoring and integration tests, build, publish. The bootstrap imports new IDs and updates metadata for the version. To correct a question's wording/key, use a new immutable ID and archive the old record; saved sessions preserve their original snapshots.

`public/downloads/vekto-question-bank.sqlite` is a standalone export with empty user-data tables, never a copy of production profiles. The adjacent manifest reports raw, eligible and official counts separately. `data/platform-seed.sql` is a maintenance import, NOT a schema migration.

## Verification

`npm run test:scoring`: all 412 answer keys, blanks, numeric equivalence, matching, ordering, positional biology scoring, excessive choices, scale boundaries.

`npm run test:platform`: local-only integration against port 8787 and a local D1 fixture. Tests ownership isolation, persisted answers/resume, stale revisions, locked reveals, repeat avoidance, idempotent completion, all four optional-subject exam variants, expired deadlines, break enforcement, full scores and real statistics. It creates isolated guest test profiles and only adjusts deadlines in the local fixture database. Never point this fixture at production.
